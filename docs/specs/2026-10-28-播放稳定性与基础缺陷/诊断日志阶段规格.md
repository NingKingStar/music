# 诊断日志阶段规格

日期：2026-10-28。版本：1.0。状态：用户已选择“本地完整记录＋一键导出”，本轮进入实现与验证；尚未完成正式测试、独立验收或生成安装包。

## 范围调整

用户要求暂缓先前的功能修复，优先补充日志，获取加载慢和中途自动跳歌的实际证据。此前[规格说明](规格说明.md)中的修复工作包不在本阶段实施。

本阶段只增加必要的观测、限量存储和导出能力，不改变音源优先级、超时、恢复次数、缓存策略、音质、自动切歌和同步删除行为。所有角色仍遵守[职责与交付标准](职责与交付标准.md)。用户本次选择作为本地记录与导出的实施授权；远程上传不在授权范围。

## 环境信息与事实边界

测试员据用户转述使用手机联机软件连接电脑，可能采用 Wi-Fi Direct。软件名称、连接拓扑、手机默认互联网出口及故障时网络切换尚未确认。不能将直连等同于手机通过电脑上网，也不能据此认定故障原因。

当前电脑无已连接的 Android ADB 测试设备。既有接口测试不构成该联机场景的手机运行证据。

2026-10-28 检查时，本地未找到本项目 APK；公开 GitHub API 返回 Release、Actions 运行及构建产物均为零。项目包含普通版和 MIUI 版 APK 构建配置，具备构建能力不代表现有可下载安装包。后续诊断包必须关联准确代码提交和签名来源。

## 需要回答的问题

1. 从点击到实际起播，时间主要消耗在何处？
2. 当前使用哪个平台、脚本和实际音质，是否发生跨平台、换脚本或降档？
3. 自动切歌来自正常结束、读取错误、恢复耗尽、用户操作、外部媒体控制，还是旧任务/事件迟到？
4. 故障前后，手机默认网络及互联网可用状态是否变化，实际请求所在网络是否可确定？
5. 播放是否读到预期资源，字节读取是否提前终止，缓存是否参与？

## 最小日志契约

| 类别 | 必需记录 | 分析用途 |
| --- | --- | --- |
| 公共关联 | 运行标识、播放会话标识、事件序号、单调时间、应用版本/提交、平台与系统版本 | 关联同一次播放，避免跨歌曲拼接日志 |
| 用户与外部意图 | 点击、下一首、上一首、拖动、暂停、停止、队列变更；操作来源和目标歌曲匿名标识 | 区分自动跳歌与用户/外部控制 |
| 起播阶段 | 点击接受、歌曲发布、下载匹配、脚本初始化、解析、探测、数据源打开、播放器准备和可用音频输出事件 | 分离接口、播放器和初始化耗时；不能将 READY 冒充出声 |
| 解析尝试 | 尝试序号、请求/实际平台与音质、匿名脚本标识、首选/后备、缓存命中、结果类别、耗时与取消原因 | 确认回退路径与等待原因 |
| 网络请求 | 请求关联标识、用途、目标服务域名、DNS/连接/TLS/响应阶段可获得的耗时、HTTP状态、Range、声明长度、读取字节量、资源匿名指纹 | 区分慢连接、慢响应、断流与资源变化；不可得字段写未知 |
| 播放状态与结尾 | 状态变化、转换原因、当前/前一歌曲匿名标识、位置、目录/播放器/资源时长及各自来源、EOF/异常类别 | 区分正常结束、短资源、断流及主动转场 |
| 恢复与切歌 | 恢复原因、已用次数/时间、是否重建、恢复前后位置、最终动作、下一首匿名标识、决定该动作的代码分支 | 解释为何恢复或为何跳歌，不改变现有策略 |
| 网络环境 | Android 默认网络变化、网络会话匿名标识、传输类型、互联网能力与系统验证状态、事件时间；有可靠观测时记录请求选定网络 | 核对联机软件启动或网络变化与故障的时间关系 |
| 播放环境 | 音频焦点与输出设备类型变化、后台/前台、可获得的省电相关状态 | 排查非音源因素；不记录设备地址或个人标识 |

网络记录须注明是系统默认网络还是实际请求绑定网络。未显式绑定或无法可靠观察的请求必须标“实际网络未知”，不能用默认网络推断。默认网络的传输类型也不能单独证明使用了 Wi-Fi Direct。

日志按状态转换或请求阶段记录，禁止每个音频数据块同步写盘。各并行阶段分别记录，总起播耗时使用同一会话时间轴，不能简单相加。

## 日志存储与导出

- 优先复用现有错误日志、播放计时和导出入口，避免两套互不关联的记录。
- 在本地保存结构化日志和简明问题摘要，导出包包含运行环境、相关播放会话及截断/丢弃记录说明。
- 使用有界队列、异步写入、轮转与保留上限；日志写入或导出失败不能中断播放或修改错误恢复结果。
- 禁止记录认证头、API 密钥、原始音源脚本、完整签名直链、SSID/BSSID、MAC、完整 IP、个人文件路径及原始搜索输入。默认用匿名歌曲标识关联；用户反馈具体歌名由其自行补充。
- 不自动上传日志。由用户主动导出和提供；接收日志后再分析，不预先收集联机软件的其他数据。

## 测试与独立验收

测试角色验证会话关联、事件顺序、错误/EOF/转场覆盖、网络变化记录、脱敏、轮转、日志故障隔离，以及开启日志前后的行为一致性。受控网络夹具与真实联机软件场景分开报告。

独立验收角色确认：一份证据能够解释目标曲目的阶段耗时、结束/失败原因和队列推进决定；未知信息明确标未知；未改变原有播放行为；没有敏感内容泄漏。真实联机场景缺证据时保持待验。

用户进一步明确的独立代码评审门槛：必须检查新增问题及直接/间接阻断风险。重点包括主线程与音频线程阻塞、锁与队列饥饿、刷新/导出/关闭死锁、取消失效、磁盘故障影响播放、后台监听生命周期、会话误归属、敏感信息泄露，以及编译/依赖注入/平台兼容。所有 P1、重大 P2 和可能阻断核心流程的问题均须退开发修正，经测试及独立复验后才可放行；一般 P2/P3 单列，不得掩盖未验证项。单元测试通过不能替代此项评审。

本轮采用以下统一工程默认值，不改变先前待确认的播放修复参数：

| 项目 | 本轮标准 |
| --- | --- |
| 启用方式 | 默认记录基础诊断，不新增必须先开启才能收集现场的步骤 |
| 存储 | 最多 5 个日志文件，每个不超过 2 MiB，总计不超过 10 MiB；最长保留 7 天 |
| 写入 | 异步有界队列，容量 1024 条；溢出丢弃并计数，不阻塞音频读取线程 |
| 单事件 | 事件名、字段集合和字段长度有界；只保存明确允许的诊断值，原始异常文本不可直接落盘 |
| 关联 | 运行、歌曲播放和请求分别关联；匿名化不暴露原歌曲标识、路径或密钥 |
| 关联确定性 | 每条记录的 `session_basis` 区分用户意图、创建时候选和未知；候选不得作为真实媒体代次证明，未知不得自动并入最近意图 |
| 导出 | 用户主动选定本地保存位置；导出当前保留文件及清单/环境摘要，注明丢弃与截断情况；导出前尽力刷新队列并说明刷新结果 |
| 取消 | 取消保存位置选择不触发写出或上传；失败清晰提示，不影响播放 |
| 兼容 | 保留现有复制错误日志入口，但新增导出包不能直接包含原有未经脱敏的消息和异常堆栈 |
| 网络 | 只增加必要的普通网络状态权限；默认网络与实际请求网络明确区分，后者不可得即写未知 |
| 验证边界 | 受控自动验证由测试角色执行；没有设备时，Android 实机导出和真实联机使用仍为待验 |

日志开销通过非阻塞队列、批量/事件写入与受控测试验证；本轮不宣称达到尚未测量的真实手机耗时或内存数值。超出存储、隐私或失败隔离标准时不能验收通过。

## 诊断包交付要求

诊断包按测试角色确认的构建命令生成，记录普通版/MIUI版、版本、提交、APK SHA-256、签名来源及验证结果。不能使用作者正式签名密钥，除非另有明确授权和可用密钥。

不同签名的包可能无法覆盖安装既有应用。交付前必须说明兼容条件；不得为安装诊断包擅自卸载测试员现有应用或清空其数据。

本轮先完成实现及独立验证，再根据可用构建环境尝试生成普通版诊断 APK。源码实现、自动测试、APK 构建与真机验收分别报告，任一环节未完成必须明确说明，不能把源码交付描述为可安装包。

## 本轮角色与交付

- 开发智能体：负责记录器、生产埋点、Android 导出和必要生产配置；对混合构建文件拥有唯一修改权，按测试角色明确需求补充测试依赖。
- 测试智能体：只维护测试及执行证据，不修改生产代码和规格；负责构建/测试命令的正式执行与结果归档。
- 文档智能体：维护本目录的统一标准、使用说明和交付索引，不修改实现或测试。
- 独立验收智能体：实现和测试交付后只读核查证据与代码，出具裁定；缺少真机证据时不得签署手机体验通过。

开发与测试通过稳定接口约定协作，标准修改由文档记录。任何一方发现对方产物的问题，均交回对应负责人修改，不越权代修。
