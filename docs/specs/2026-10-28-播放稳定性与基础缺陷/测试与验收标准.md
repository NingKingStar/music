# 测试与验收标准

本文配套[规格说明](规格说明.md)与[职责与交付标准](职责与交付标准.md)。以下是计划标准，不是已执行或通过的报告。待确认阈值只能引用冻结决策，不得临时自行填写。

## 测试原则与现有覆盖

测试角色负责用例、夹具、执行与缺陷报告；独立验收角色核对标准与证据并裁定。开发者的编译成功、测试代码存在或接口调用成功均不能替代正式测试和独立验收。

现有测试已覆盖同档竞速、取消后脚本复用、首选预热、部分读取失败清除直链、资源变化禁止字节拼接等。主要缺口是服务层错误/转场事件组合、连续播放场景、端到端起播计时、真实设备恢复体验，以及本轮新增缺陷的精确回归。不能把现状写成“完全没有断流测试”。

## 确定性夹具

- 音频采用自行生成或可再分发材料，固定歌曲身份、目录时长、实际时长、编码、长度与校验值，不使用用户凭据。
- 受控 HTTP 服务可注入首次响应延迟、分块延迟、断连、短响应、合法 EOF、错误长度、Range/206/416、过期链接、资源版本变化、429/5xx 与条件上传冲突。
- 区分故意截短资源与传输截断：前者可能合法返回 200，后者可能产生读取错误；两类分别验证。
- 允许使用可控时钟和可控协程调度推进超时，避免靠真实等待偶然通过。
- 跨端 URL 夹具共用输入和期望身份；上传夹具既支持精确逐字节比对，也支持峰值内存采样。
- 上传客户端与接收服务的内存分开测量；测试断言不能自行把完整大文件装入被测客户端堆。媒体、快照和脚本替身均登记夹具散列。
- 实际音源接口探测与确定性回归分开，记录脚本哈希和环境，不保存脚本密钥、签名直链或完整响应正文。

## 执行层次与环境

1. 纯逻辑/协程测试：恢复预算、取消、会话隔离、合并和解析规则，使用受控时钟。
2. 模块集成测试：实际 HTTP 客户端、资源身份、缓存、条件上传和持久化，核对真实请求与文件内容。
3. Android 服务层测试：播放器监听器与错误/EOF/转场事件组合；不能只验证数据源抛出异常。
4. 平台验证：Android 真机起播/中途恢复、后台及暂停交互；Windows VLC 连续循环及双端路径/上传。未取得设备或原生库时本层保持待验。

测试角色在标准冻结后核对实际 Gradle 任务图并维护命令清单；不得把未核验的任务名当已可执行命令，也不以打包任务替代测试任务。

性能记录须包含设备型号/API/内存、网络条件、应用及脚本哈希、冷热定义、样本分组、失败/取消/超时数量、中位数及高分位。不得只统计成功快速样本；失败与被取消样本单独报告。

## 证据包

每份证据包含角色与智能体标识、工作包/用例编号、规格版本、代码提交、构建产物 SHA-256、环境、命令、开始/结束时间、原始结果位置、失败/跳过清单及限制。日志需按会话可关联，并脱敏。

尚未提交的本地候选须额外附变更/新增源文件的 SHA-256 清单，并在测试前后核对一致；基线提交本身不能代表未提交实现。独立验收核对同一清单，源码再变化则相关证据失效。

执行报告中的状态只允许已执行通过、已执行失败、跳过、未执行。下载工具链、源代码走读、编译成功、Node 宿主加载音源和实际手机播放分别记录，禁止混称。

缺陷报告至少给出前置条件、复现步骤、期望/实际行为、会话标识、影响提交和最小证据。测试不直接修复生产缺陷，验收不直接修复测试资产。

## 独立验收与阻断规则

- 验收对象必须是测试报告对应的集成提交和产物；任何不一致均退回补证据。
- 每个本批需求必须有对应已执行证据。未确认的行为或阈值、未执行/跳过的必需平台验证、凭据泄露、数据损坏、无界恢复、错误资源字节拼接均阻断对应工作包通过。
- 验收角色只能给出通过、不通过或待补证据；不得用“基本通过”隐去必需缺口。
- 无 Android 设备时，可以核验代码与接口证据，但播放-01/02/03的真机起播、恢复和连续播放保持待验。Windows 通过不能替代 Android 验收。
- 一个工作包验收通过不表示其他工作包、整批或发布已通过。发布授权另行处理。
- 若要求实际阻止合并，须额外核对仓库分支保护或规则集，将对应检查设为必需检查；仅新增工作流不代表合并门禁已经生效。无权限配置时明确登记待配置，不宣称完成。
